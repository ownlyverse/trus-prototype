# 프로젝트 규칙 (Living Rules)

> CLAUDE.md를 린하게 유지하기 위해, **영역 한정·상세 규칙**은 여기에 둔다.
> 하네스(execute.py)가 이 파일을 매 step 프롬프트에 가드레일로 주입한다.
> CLAUDE.md와 동일한 작성 원칙을 따른다: 구체적·검증 가능, 모순 없음, bloat 금지.

## 규칙 목록

- 인라인 `<script>`를 고친 뒤에는 그 스크립트만 임시 파일로 뽑아 `node --check`를 돌린다 (이유: 문법 오류가 나면 화면이 통째로 백지가 되는데 브라우저 콘솔을 안 보면 모른다).
- `localStorage` 키는 `trus_` 접두사를 붙이고, 스키마에 `v` 필드를 둔다. 읽을 때 `v`가 다르면 무시하고 빈 상태로 시작한다 (이유: 목데이터 스키마가 자주 바뀌는데 옛 데이터가 남아 화면이 깨진다).
- `localStorage` 쓰기는 `try/catch`로 감싸고 실패 시 사용자에게 토스트로 알린다 (이유: 프라이빗 모드·용량 초과에서 조용히 실패하면 저장된 줄 안다).
- 목데이터 상수는 파일 상단 한 구역에 모으고 렌더 함수와 섞지 않는다.
- 새 기능을 나중에 껐다 켜야 한다면 코드를 지우지 말고 파일 상단 플래그 상수(`const SOCIAL = false`)로 분기한다. 플래그에서 파생되는 값(단계 수, 탭 개수 등)을 하드코딩하지 않는다.
- 이미지를 새로 인라인할 때는 base64로 박고 외부 경로를 남기지 않는다 (이유: 이 저장소의 HTML은 파일 하나만 열어도 동작해야 한다).
- 사용자 확인이 필요한 파괴적 동작(하이라이트 덮어쓰기, 삭제 등)은 `confirm()` 대신 화면 안 UI로 묻는다 (이유: 브라우저 모달은 자동화 세션을 멈춘다).
- 지면·본문처럼 사용자가 드래그로 선택하는 영역에는 `cursor: text`를, 클릭 대상에는 `cursor: pointer`를 명시한다.
